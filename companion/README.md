# Ferb Link (companion app)

Developer notes for the Ferb Link app. To install and use it, see the [main README](../README.md).

Ferb Link (`dev.abhay.ferblink`) holds the internet permission Ferb doesn't have, and passes Ferb's requests to your computer's model server over Tailscale. Without Ferb Link, when it's switched off, or when your computer can't be reached, Ferb answers on the phone.

## The screen
Until it's connected, it shows only how to connect (pair with `server:pair`'s QR code, Paste link, or Enter by hand), plus Privacy and the licences. A `ferblink://pair?url=…&key=…` link opens a confirmation showing the computer's name in full (any app can open such a link).
1. The main switch, **Use your computer**, and the status card: whether the computer answers, the model, its state (Ready, Asleep, Unloaded), and **Takes voice** when the server is in full mode (`mise run server:mode full`). Refresh checks again; Unload stops the model on the computer to free its memory, and the next request starts it again.
2. **Your computer**: one row with the computer's name; tap it to change the address or key.
3. **Recent** lists what went to the computer, recordings included with what was heard (kept in memory only); tap a row for details.
4. **Advanced** (closed unless Jev is on): a test request with three sample tools (timer, alarm, flashlight; tap the answer for the time and the confidence stand-ins), and Jev.
5. **About**: Privacy (the repo's `PRIVACY.md`), and Open-source licences with the version: every library in the APK and the Apache License 2.0's text (`Licences.kt`, `res/raw/apache_2_0.txt`, a copy of the repo's LICENSE).

All of the screen's words are in `res/values/strings.xml`, with the terms shared with Ferb at its top. The errors from `ServerClient` stay in code: they're part of the contract, and Ferb shows the same words in its chat.

## For Ferb: `LinkContract`
One `ContentResolver.call` on `dev.abhay.ferblink.link`; there's no service to bind to. See [`LinkContract.kt`](app/src/main/kotlin/dev/abhay/ferblink/LinkContract.kt).
- `status`: no network. Returns `version`, `enabled`, `configured`, `model` (the model the server last named; empty if none yet), and `audio` (whether the server last said it takes audio; refreshed by `check`, `wake` and answers), and `model_state` once one has been seen: `loaded`, `asleep` (also while loading) or `unloaded`. It says `loaded` only if seen loaded in the last 270 s, since the server puts the model to sleep after 300 s idle without telling the phone; anything else can mean a cold load, so wait longer (up to 60 s). `check` returns it too, live when the computer answers.
- `complete`: takes `request`, `tools` (the JSON array of schemas Needle 3 gets), and optionally `facts` (added to the system prompt) and `timeout_ms` (the answer timeout, 1–60 s; 30 s without it). Returns `reply`, JSON shaped like Needle 3's (`success`, `function_calls`, `confidence`, `error`), plus `first`, `mean`, `text`, `model`, `ms` and `source: "laptop"`. It blocks until the computer answers (3 s to connect at most), so call it off the main thread. A `request` over 2000 characters (`MAX_REQUEST_CHARS`; also for `rewrite` and `decide`) is a bad request, and so is one the model's context can't hold. On any failure `success` is false, `error` says why in a few lowercase words for a chat bubble ("timed out", "can't reach your computer", "key refused", "server error 500", "model loading", "bad request: …"), `error_detail` in a sentence, and `error_kind` is one of:
  - `off`, `not_set_up`;
  - `bad_request` (no request, or the tools aren't a JSON array);
  - `unreachable` (no connection), `timeout` (connected, no answer in time);
  - `auth` (the API key was refused), `server` (any other non-200, including 503 while the model loads), `bad_reply` (not the expected JSON).
- `check`: whether the computer answers now (`/health`, `/v1/models` and `/props`, 2 s each; doesn't wake the model). Returns `version`, `reachable`, `model`, `audio`, and `error` and `error_kind` when it isn't reachable.
- `wake`: returns `version` at once and, in the background, loads the model if it's asleep (about 2 s, once 12 s). Ferb calls it when the user starts recording.
- `transcribe`: takes `audio` (a ByteArray, at most 512 KB and 30 s: Opus in OGG, AAC, or anything Android decodes; WAV is passed on as it is once its header says it's within 30 s). Decoding stops as soon as it passes 30 s or about 6 MB of sound, so a long low-bitrate file can't fill memory, `audio_mime`, and optionally `timeout_ms` (15 s without it) and `hints` (reserved, ignored). Ferb Link decodes it to 16 kHz mono WAV, the server's format. Returns `reply`: `success`, `heard` (what was said, Hindi in Latin letters), `text` (the same request as a plain English command, equal to `heard` for English speech), `model`, `ms`, `source`, and `error` and `error_kind` as for `complete`. No speech gives empty `heard` and `text`: recordings whose loudness hardly changes (silence, room noise, hum) are answered without the model (`SpeechCheck`), and the model says first whether anyone spoke. Debug builds also take `audio_base64` (a string) for trying it from `adb shell`.
- `decide`: TypeSafe's Jev, a cloud model, picks the tool (Ferb's "Use Jev to select the tool", which sends every request while it's on). It's off by default: the user turns it on in Ferb Link's Jev section and gives a key. Takes `request`, `tools` (as for `complete`; only each tool's name and description are sent to TypeSafe) and `timeout_ms` (3 s without it, at most 10 s). Returns `reply`: `success`, `choice` (a tool's name or `none`), `probabilities`, `options` (in the order asked, shuffled per request because Jev leans to the first), `model` (pinned to `jev-1.13.0`), `ms`, `source: "jev"`, and `error`, `error_detail` and `error_kind` as for `complete`. Every call's cost is counted on the phone, one call at a time. A call goes only if a ceiling on its cost (every byte of the body a token) still fits under the cap, so the spend never passes it; one that doesn't fit fails as `off` while Jev stays on. At the spending cap ($3 by default, set in the card), Jev turns itself off: `decide` fails as `off`, and `status` says `jev_off_reason: "cap"`. `status` also has `jev`: on and with a key.
- `rewrite`: a typed (Hinglish) request as plain English commands, one per action, for Needle 3: the computer's model with the rewrite prompt (`LinkContract.REWRITE_VARIANT`, v2), Hindi amounts worked out in code first. Takes `request`, `now` (optional, "2026-10-16T09:00 (Friday)"; the phone's clock without it) and `timeout_ms`. Returns `reply`: `success`, `commands` (empty when nothing is asked), `invented` (numbers and names in the commands that the request didn't hold: don't run those), `model`, `ms`, `source`, and `error`, `error_detail` and `error_kind` as for `complete`.
  - With `instructions` (Ferb's own prompt, e.g. GeminiRewrite, at most 16000 characters) it runs that prompt instead: the instructions as the system message, the request as it is as the user message, greedy (temperature 0, top_k 1), at most `max_tokens` tokens (default 40, at most 256), no Amounts, `now` ignored. `commands` holds the first line as one command, or nothing for NONE, `invented` is always empty (the prompt writes Hindi amounts as numbers), and the reply adds `raw` (the model's text, for Ferb's own parsing) and `instructions: true`. If the model hits `max_tokens` before ending the first line, the call fails ("answer cut off", bad_reply) so half a command never runs. An older Ferb Link ignores `instructions` and answers with v2, without the echo.
- **Version:** additions (extras, reply fields, error kinds, methods) keep `version` at 1; a changed meaning bumps it. An older Ferb Link throws `IllegalArgumentException` for a method it doesn't have.
- Ferb needs `<queries><package android:name="dev.abhay.ferblink" /></queries>` to see the provider.
- **Who may call:** apps signed with the same key (`PackageManager.checkSignatures`), so Ferb from the same releases, or debug builds from the same machine. Debug builds also accept `adb shell` (`mise run companion:try "set a timer"`).

## How it asks the server
Every request names the model (the server's router needs it): the last one the server named, or the first in `/v1/models`. Like Ferb's bench (`tool-check/bench.py`), so the bench's results hold: the same system prompt, the tools as OpenAI functions, `tool_choice: auto`, temperature 0, 256 tokens at most, thinking off, `logprobs` on. The bench's three stand-ins for a confidence come back: the weakest token (`confidence`), the first token (`first`) and their `mean`. Not ported yet: the bench's fallbacks for models that write calls as text (FunctionGemma's own format, Hammer's list).

Recordings go with their own prompt (`ServerClient.TRANSCRIBE`), at temperature 0, with a JSON schema. Any Devanagari the model writes anyway is converted to Latin letters on the phone (`Latin`, with ICU, as Ferb does for contacts; an ASCII-only schema pattern made llama.cpp fail some answers with HTTP 500). The answer is held to `{speech, hindi, heard, text}` in that order, so the model decides whether anyone spoke before writing words; asked only to leave the fields empty, it turned silence and noise into commands. When nothing was Hindi (by the model, or a list of common Hindi words), `text` is set to `heard`: asked to restate English, the model sometimes changed its meaning.

## Network
Plain HTTP, only to Tailscale names (`*.ts.net`, `res/xml/network_security_config.xml`), because the tailnet already encrypts it; HTTPS anywhere. The app rejects other `http://` addresses (a raw `100.x` address or a short name like `my-laptop` won't do).

**Planned, after 0.1: reach the computer by its Tailscale IP when its name won't resolve.** With Android's Private DNS set to a provider (NextDNS, for example), every lookup skips Tailscale's DNS, so the computer's name doesn't resolve. For now the status card says to set Private DNS to Automatic (`Guidance`). The design:
- `server:pair` adds `ip=` to the link. `Pairing` accepts it only within Tailscale's range, 100.64.0.0/10, and `LinkSettings` keeps it. Links without it still pair, just with no fallback.
- `ServerClient.send` moves from HttpURLConnection to OkHttp, and the URL keeps the `….ts.net` name. The network security config and the name Tailscale Serve needs stay the same. Serve answers 404 to a request by IP alone and 200 when the request names the computer, and the key check is unchanged.
- OkHttp's `Dns` asks the system first. Only on `UnknownHostException`, and only for the paired name, does it return the paired IP.
- Why not without OkHttp: the config can't list an address known only at pairing, or a range of them. With HttpURLConnection the request would go to `http://100.x`, which is checked against the IP, so cleartext would have to be allowed everywhere.
- To do: tests for parsing and checking `ip=`, and for the fallback happening only on a failed lookup for the paired name. Add OkHttp and Okio to Credits and `Licences`. Run `check-reflection.sh` and a smoke test of the release build on the phone. If the computer's Tailscale IP changes (rare), pair again.

## Testing
Five tiers. Most tests check one piece; models are evaluated only when tuning them.

| Tier | What | When | How |
|---|---|---|---|
| Unit | `Amounts`, `SpeechCheck`, `Latin`, `AudioDecoder`'s steps around MediaCodec, request building and reply parsing, error kinds, timeouts and connection reuse (`ServerClient` against a fake llama-server), the provider's calls and caller check (`LinkCalls`). No model, server or phone. | Every change | `mise run companion:test` |
| Contract | `contract/v1/`: one JSON file per case, each method's extras and result, and every error kind. `ContractTest` checks `LinkCalls` gives exactly those; Ferb's tests read a copy (`mise run link:contract-check` / `link:contract-sync` in Ferb). | Every change, in the same run | `mise run companion:test`; after a contract change, `mise run companion:contract-write`, review the diff, tell Ferb |
| Device | What only Android does: a ferblink://pair link reaching the app, the "replaces …" warning, Paste link's clipboard read (`PairingLinkTest`, which opens the screen), hints remembered across a restart (`HintsTest`, no screen). They run inside the installed app on its real settings, and put them back. | After changing those | `mise run companion:device-test` (or `… HintsTest` while the phone is in use) |
| Model evaluation | The transcribe prompt and schema, the complete system prompt, tool configuration: the harness, synthetic-voice clip runs, `server:chat`. | Only when tuning a prompt or tool config | `mise run companion:harness`, `mise run server:chat` |
| End to end | `mise run server:ping`, and the ~6-case smoke checklist on the phone (in Ferb's repo). | Before an install-worthy release | by hand |

GitHub Actions runs the unit and contract tests and Android lint on every push and pull request (`.github/workflows/ci.yml`), with no secrets and no signing.

A miss found in a model evaluation becomes a unit test of the code that should have caught it (most are in `AmountsTest`), not a new evaluation case. Gradle runs without daemons (`--no-daemon`, and the Kotlin compiler in-process): nothing outlives a build to crowd the model server's memory, and never run `./gradlew --stop`, which stops Ferb's builds too.

## Help on the screen
- **Connection errors:** under the status card's error, one line saying what to do (`Guidance`), only when the error's own detail doesn't already say it: Tailscale off on the phone (no VPN up), Private DNS set to a provider (Tailscale names won't resolve), the server not on the tailnet, a refused key (pair again), a loading model (try again), the logs for other server errors.
- **Jev (TypeSafe)**, under Advanced: off by default. Without a key it's one row that opens the key dialog, which says first what would leave the phone. With a key: the switch, the key and the spending against its limit ($3 by default, shared by every use), and a Test (one small, counted request). Under it, what leaves the phone when it's on: the text of every request while Ferb's "Use Jev to select the tool" is on, and the tools' names and descriptions, to TypeSafe in the US.
- **First-use hints** (`Hint`), each shown once until "Got it": the main switch, voice (or how to turn it on), Unload, and the test request.
- **Pairing:** a "Connect to your computer" card until an address and key are saved, with Paste link (for camera apps that show a `ferblink://` link without opening it), Enter by hand, and the setup guide (the README's "Install on your phone").

## Logs
`adb logcat -s FerbLink`: each call's arrival and total time, and each HTTP request's connect, send, wait and read times. Connections are kept and reused (`send()` no longer closes them): the first request after a while takes about 50–100 ms to connect over the tailnet, the next ones 0–2 ms.

## On the computer, without the phone
`mise run companion:harness in.jsonl [out.jsonl]` runs Ferb Link's own `complete` and `transcribe` code (`LaptopHarness`, a model evaluation: left out of `companion:test`) against the local server: one JSON object per line in, one Ferb Link reply per line out.
- `{"id": "a1", "request": "sava saat baje utha dena", "tools": [...], "facts": "...", "timeout_ms": 10000}` → the `complete` reply, plus `"sent"`: the request after `Amounts.forRequest`, as the model gets it.
- `{"id": "v1", "audio": "clip.ogg"}` → the `transcribe` reply (`heard`, `text`). The file is decoded with ffmpeg to 16 kHz mono WAV, and ICU's transliteration goes through `uconv`; the rest (`SpeechCheck`, the prompt, `Latin`, `Amounts`) is the phone's code.
- `{"id": "d1", "method": "decide", "request": "...", "tools": [...], "timeout_ms": 10000}` → TypeSafe's Jev (`JevClient`, a cloud model: **it costs money**), not the local server. It returns `choice`, `probabilities`, `options` (in the order asked), `ms`, `input_tokens`, `usd` and `estimated`. Only the request and each tool's name and description are sent. The key is read from `~/.config/ferb-link/typesafe-key`, which only the user writes. Every call goes in `~/.config/ferb-link/jev-spend.json`. A run whose estimate (twice JevClient.estimateTokens, fitted on the smoke run) would take the tests past their $1 is refused before anything is sent. A call costing over 10× its estimate stops the run, and the rest give `{"skipped": …}`. `--limit N` sends at most N; `--dry-run` sends nothing at all (complete and transcribe lines included) and prints the decide count, its estimated cost and the number of other lines. The task prints the ledger's total at the end.
- `{"id": "r1", "method": "rewrite", "request": "...", "now": "2026-10-16T09:00 (Friday)", "variant": "v1+shots", "tools": [...]}` → an experiment (`Rewrite`): Gemma writes the request as plain English commands for Needle 3, one per action, or none when nothing is asked. Returns `commands`, `invented` (numbers and names in the commands that the request doesn't hold, worked-out dates aside), `sent` (after `Amounts.forRequest`), `raw` and `variant`. Variants: `v1` (the default here), `v2` (what Ferb gets: never adds a fact the request lacks; questions only words answer give no command), and the set-aside experiments `v2.1` and `v3` (`Rewrite.kt`), plus `+shots` (examples), `+tools` (Ferb's tool names), `+think` (thinking on) and `+free` (no JSON schema).
- `{"id": "i1", "method": "rewrite", "request": "...", "instructions": "..." or "instructions_file": "/path", "max_tokens": 40}` → the provider's instructed rewrite, answered as `rewrite` answers Ferb.
- `{"id": "s1", "method": "schema-call", "request": "...", "now": "...", "tools": [...], "rewrite": false}` → B's call as enforced JSON instead of native tool calls (which get no grammar for Gemma 4): `calls` (each `tool`, `arguments`, `when`), and with `rewrite` true optionally `commands` instead. A bench baseline only (`SchemaCall` and `TimeFormat` live in the test sources).
- `{"id": "t1", "method": "transcribe-text", "heard": "..."}` → the transcribe prompt with the heard text in place of a recording, for checking its "text" rules on the audio bench's heard lines (the audio wasn't kept). Not what the phone sends.
It starts Gradle without a daemon (about 40 s), so batch the lines. Models run one at a time: don't run it during a bench.
